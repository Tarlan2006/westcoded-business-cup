# Задача: аудит и доводка проекта MyPal перед сдачей на хакатон

Дизайн, цвета, шрифты, тексты и общий стиль НЕ менять. Работаем над деталями, надёжностью и чистотой кода.

Принцип по каждому этапу: подумал → сделал → проверил → ещё раз подумал, как сделать лучше. Все находки веди в AUDIT.md с приоритетом:
**P0** блокер сдачи (сломано, утечка, не открывается), **P1** заметный дефект, **P2** качество, **P3** косметика. Сначала закрывай P0 и P1. После каждого этапа отдельный маленький коммит.

## ЭТАП 0. Базовый замер (до правок)
- `npm run build`, размер бандла, Lighthouse (mobile) для главной и ключевых экранов: Performance, Accessibility, Best Practices, SEO. Запиши цифры "до".
- Автосканеры: `npx unlighthouse --site <боевой адрес>` (или lighthouse CLI по основным маршрутам) и `npx github:nurkamol/seo-audit <локальный/боевой адрес> --md seo-audit.md`. Результаты приложи в AUDIT.md. Если нет интернета, прогони локальную сборку (`npm run preview`).

## ЭТАП 1. Безопасность и окружение (P0)
- В репозитории и в собранном бандле нет секретов и ключей (grep по GROQ, KEY, SECRET, token), `.env` в `.gitignore`, нет `.env`, `.git` и исходных карт на проде (`curl <адрес>/.env` и `/.git/config` не отдают содержимое).
- В продакшен-бандле нет `console.log`/`debugger`, ссылок на localhost, staging и старый адрес mission-control.
- HTTPS работает, http редиректит на https.
- Заголовки (через Worker или `_headers`): `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options` или CSP `frame-ancestors`, `Permissions-Policy` (микрофон только для нашего origin, камера и геолокация off). CSP добавляй только если не ломает YouTube-встраивание и озвучку; проверь вручную.
- CORS в worker только для разрешённых адресов, лимиты запросов, таймауты, ошибки без стектрейсов.
- Заметки родителя и данные ребёнка не уходят на сервер, в запросах /api только вопрос; проверь Network.
- Страница 404: неизвестный путь показывает дружелюбный экран MyPal и кнопку "Home"; API-ошибки возвращают корректные коды (не 200 с ошибкой).

## ЭТАП 2. SEO, превью ссылки и метаданные (P1)
- Уникальные `title` и `description`, `lang="en"`, viewport, theme-color, canonical.
- `og:title`, `og:description`, `og:image` (1200×630 с маскотом, лежит в public), `twitter:card=summary_large_image`. Превью должно корректно открываться при отправке ссылки в Telegram и WhatsApp.
- favicon, apple-touch-icon, manifest.
- `robots.txt` без `Disallow: /` и без noindex; `sitemap.xml` с финальным боевым адресом.
- Один `<h1>` на экран, логичная иерархия заголовков.

## ЭТАП 3. Адаптация: 360×740, 390×844, 768×1024, 1280×800, 1440×900
- Playwright-скриншоты каждого экрана на каждом размере. Ищи: горизонтальный скролл, обрезанный или налезающий текст, перекрытия, лишние пустоты и зазоры, кнопки меньше 44px, ломаные сетки, фиксированные высоты.
- Исправь так, чтобы везде было чётко, без зазоров и обрезаний. Учти `100dvh` вместо `100vh`, safe-area iPhone, ландшафт телефона, увеличенный системный шрифт.
- Mobile-first, без горизонтальной прокрутки ни на одном экране.

## ЭТАП 4. Мелкие детали интерфейса (профессиональный уровень, стиль не менять)
- Единая шкала отступов (4/8/12/16/24/32), единые радиусы, высоты кнопок и инпутов, выравнивания. Убрать случайные значения.
- Кнопки: hover, active (утапливается), focus-visible, disabled, плавные transition 150-250ms, одна кривая easing на весь сайт.
- Появление элементов и переходы между экранами: мягкий fade/slide 200-300ms, без прыжков и мерцаний, без layout shift. Нажатие на любой элемент даёт мгновенную реакцию.
- `prefers-reduced-motion` везде.
- Состояния loading, empty, error для голоса, Ask, видео и сети: короткие понятные тексты, без технических ошибок на экране.
- При смене экрана скролл вверх, фокус на заголовке.

## ЭТАП 5. Производительность
- Картинки WebP, заданы width/height (нет CLS), lazy-loading ниже первого экрана, шрифты с `font-display: swap` и preload критичных, сжатие gzip/brotli (Cloudflare), долгий cache для хешированных ассетов.
- Основной JS не больше прежнего размера (было ~93 KB gzip), игры и тяжёлые экраны через `React.lazy`. Нет неиспользуемых зависимостей.
- Цели Lighthouse mobile: Performance ≥ 85, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 90. Если не дотянул, объясни в отчёте.

## ЭТАП 6. Доступность (A11y)
- У значимых картинок `alt`, у декоративных `alt=""`, у полей `label`, видимый focus при Tab, все кнопки доступны с клавиатуры, `aria-label` у иконок-кнопок.
- Контраст текста ≥ 4.5:1, кнопки ≥ 44px, не полагаться только на цвет.
- Озвучка не мешает экранным читалкам; у hold-кнопок есть текстовая альтернатива.

## ЭТАП 7. Чистота кода
- Найди неиспользуемые файлы, компоненты, функции, переменные, зависимости, CSS и ассеты (`tsc --noUnusedLocals`, eslint, knip или depcheck, поиск по импортам).
- Каждая находка: используется или нет. Не используется → удалить (старый Bleep/робот, мёртвые игры, дубли, закомментированный код, неиспользуемые mp3 и картинки). Сомневаешься → не удаляй, перечисли в отчёте.
- Дубли логики вынеси в общие функции/хуки только там, где код станет проще; рабочую логику не переписывай.
- TypeScript без `any` где легко; `npm run build`, `tsc` и lint без предупреждений.

## ЭТАП 8. Готовность продукта к сдаче
Критерии жюри: продукт работает 40%, что продаём 20%, кому 15%, как зарабатываем 15%, новизна 10%.
- Прогон полного пути: Greeting → Setup (nickname обязателен) → сессия по таймеру → видео+квиз → миссия → Complete → Hub → игры → Ask → конец сессии → снова Setup. Ничего не ломается ни на одном шаге, при перезагрузке, при потере сети, при отказе в микрофоне.
- Работает без логина на боевом адресе; консоль без ошибок и предупреждений; mp3-клипы грузятся; /api отвечает быстрее 8 с; нет слов Bleep, Mission Control, "ad-free", "zero ads".
- Скрипт `scripts/smoke-prod.mjs` (Playwright) прогоняет путь автоматически и лежит в репозитории (`npm run smoke`).
- Мониторинг: простая проверка доступности (например, UptimeRobot-ссылка в README, если подключена).

## ЭТАП 9. README.md (главный файл для жюри, на английском)
Название и слоган MyPal; проблема и для кого (работающие родители в США, дети 1-8); решение и ключевые фичи; как зарабатываем (тарифы подписки); скриншоты (папка `docs/screens`); живая ссылка; как запустить локально (`npm i`, `npm run dev`, переменные окружения без значений, `.env.example`); стек и короткая схема архитектуры; структура папок; как деплоить; приватность детей (COPPA-подход: никнейм вместо имени, локальное хранение, нет камеры и геолокации); ограничения и планы. `DEPLOY.md` обнови.

## ЭТАП 10. Финальный проход
- Повтори этапы 1-8 целиком на итоговой версии, замерь Lighthouse "после". Всё, что нашёл на втором проходе, исправь.
- Подробный `AUDIT.md`: что проверено; таблица находок с приоритетами P0-P3 и статусом; что исправлено; что удалено (списком); что осталось и почему; размер бандла и Lighthouse до/после; результат smoke-теста; скриншоты.

## Правила
Не менять дизайн, цвета и тексты (кроме багов и текстов ошибок), не ломать рабочую логику. Маленькие коммиты без Co-Authored-By. Без деплоя, жди команды "деплой". Если пункт нельзя проверить (нет доступа, нужен ключ), напиши это в отчёте, а не пропускай молча.
