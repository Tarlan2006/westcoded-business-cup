# Аудит интерфейса AIdos

Проверены маршруты ребёнка и родителя в казахской и английской версиях. Основные изменения касаются выбора следующего действия, чтения длинных подписей и управления с телефона.

## Что изменилось

## Как проверяли

Итоговый проход завершился без ошибок консоли и выходов проверяемого текста за границы. Всего 770 сочетаний состояния, языка и окна. Все 6404 замера интерактивных элементов уложились в выбранный минимум 44×44 CSS-пикселя. Сборка, TypeScript, lint и проверка 1065 ключей перевода прошли.

- В Chromium пройдено по 55 экранов и состояний на казахском и английском. Окна 320×740, 360×740, 369×800, 390×844, 768×1024, 1280×800 и 844×390. Включены приветствие, анкета с длинным именем, каталог игр, видео и ошибки проигрывания, все игры и результаты, награда, гараж, Ask, родительская модалка, планы, конец сессии, конфиденциальность и 404. [Измерения по экранам](screens.csv)
- Проверены размеры интерактивных элементов, края текста в кнопках и заголовках, горизонтальная прокрутка, доступные имена кнопок и ошибки консоли. Для флажка внутри связанной подписи измеряется вся нажимаемая область. Один и тот же элемент при разных размерах окна считается отдельным измерением.
- В Chromium и WebKit отдельно пройдены приветствие и анкета с клавиатуры. Размер текста в анкете увеличен до 200%, использовано длинное имя. На ширине 320 px на обоих языках проверены границы подписи автопоказа и переключение его состояния.
- Оба длительных сценария выполняются с уменьшенной анимацией. Внешнее видео и распознанная речь в тестах подставляются. Проверка контраста охватывает названные семейства кнопок. Физические устройства, VoiceOver и просмотр реальных видеопотоков в объём этих измерений не входят.

### Повтор проверки

На запущенной локальной версии задайте `I18N_URL` и, при необходимости, `CHROME_PATH`. Для проверки всех состояний задайте `I18N_DESIGN_AUDIT=1` и `I18N_SCREENS` с путём для новых снимков, затем запустите `node scripts/i18n-e2e.mjs`. Для проверки анкеты и клавиатуры выполните `node scripts/design-readability.mjs`. Для повтора в установленном Playwright WebKit задайте `DESIGN_BROWSER=webkit`.

## Источники и применение

- В открытом веб-рендерере Swift DocC ширина содержимого привязана к доступному месту. Для AIdos взят этот принцип и проверены собственные точки перестроения с реальными названиями игр. [Swift DocC Render, исходный код адаптивной сетки](https://github.com/swiftlang/swift-docc-render/blob/main/src/styles/core/_breakpoints.scss)
- GitHub Primer разделяет расстояния внутри элементов управления и интервалы между группами. В AIdos это применено к полям страниц, шапкам, каталогу игр и тексту для родителей. [Primer, руководство по переменным дизайна](https://github.com/primer/primitives/blob/main/DESIGN_TOKENS_GUIDE.md)
- Apple рекомендует оставлять свободное место вокруг действий и выделять наиболее вероятный следующий шаг. Это послужило основанием убрать дублирование на награде. Рекомендация Apple для нативных интерфейсов — 44×44 пункта. Для браузерных замеров AIdos использован ориентир 44×44 CSS-пикселя. [Apple HIG, кнопки](https://developer.apple.com/design/human-interface-guidelines/buttons) · [Apple, примеры читаемости и компоновки](https://developer.apple.com/design/tips/)
